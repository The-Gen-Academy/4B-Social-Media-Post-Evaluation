# 4B: Social Media Post Evaluation

This project builds a systematic evaluation loop for social media posts generated by an n8n workflow. It now includes **Jev-as-a-Judge**: TypeSafe's decision model scores the five rubric dimensions and classifies failures; application code calculates PASS/FAIL and flags uncertain results for review.

```text
Generate → Score → Analyze failures → Improve the prompt → Re-run → Compare
```

## Run Jev-as-a-Judge

### In n8n

1. Import **Social Media Jev Judge Only.json** to grade existing outputs, or **Social Media Post Generation with Jev Judge.json** to generate and grade posts.
2. In **Call Jev**, select an HTTP Header Auth credential with name `Authorization` and value `Bearer YOUR_AI_GATEWAY_API_KEY`. The workflows use [Vercel's TypeSafe-compatible API](https://vercel.com/docs/ai-gateway/sdks-and-apis/typesafe). The generation variant also needs your OpenAI credentials in both model nodes. Direct TypeSafe setup is covered in the integration guide.
3. Export the workbook's **Evaluation Log** tab to CSV. Include `User_Input` and `Model_Output`; add `Reference_Facts` with the approved facts needed to verify the post.
4. Run the workflow's form and upload the CSV. Download the binary output from **Convert to Excel** (the inherited node name; the file is CSV).

Human grades and `Status` remain in their original columns. Judge outputs use `Jev_*` columns. The generation variant keeps populated posts, generates missing posts with a topic, and skips empty rows. It retains the existing generative critic for revision advice; Jev evaluates the final text. No workflow publishes posts.

### From the command line

Requires Node.js 22.9 or newer (Node 24 recommended).

```bash
npm ci
cp .env.example .env
# Configure one provider in .env using your editor (see below).
npm run judge -- --input examples/posts.csv --output results/first-run.csv
```

| Connection | `.env` settings |
| --- | --- |
| Vercel AI Gateway | `JEV_PROVIDER=gateway`, `AI_GATEWAY_API_KEY`, `JEV_MODEL=typesafe-ai/jev-1.13.0` |
| Direct TypeSafe | `JEV_PROVIDER=typesafe`, `TYPESAFE_API_KEY`, `JEV_MODEL=jev-1.13.0` |

Use the key for the selected service. If Gateway returns `customer_verification_required`, enable a payment method in the Vercel account before retrying. Secrets stay in the ignored `.env` file or n8n credentials.

The output CSV contains scores, confidence, review flags, the resolved model version and the raw API response. A sibling `.summary.json` reports human-label agreement and disagreements. Example posts are fictional fixtures, with illustrative labels; their results are not a benchmark.

Inspect the exact requests without a key or network call:

```bash
npm run judge -- --input examples/posts.csv --output results/preview.csv --dry-run
```

To compare an n8n output with its human labels:

```bash
npm run judge -- --input downloaded-jev-results.csv --report-only
```

See the [integration guide](docs/jev-integration.md) for score mapping and calibration. A successful test suite verifies the integration; it does not establish Jev's accuracy on your dataset.

## Evaluation Workflow

### 1. Generate posts

Import the JSON workflow into n8n and run it for each test topic. Record the generated content in the workbook’s `Model_Output` column.

### 2. Score every post

Score each post from **1 (Poor)** to **5 (Excellent)** across five dimensions:

| Criterion | Evaluation question |
| --- | --- |
| Factual Correctness | Does the post contain hallucinations, incorrect dates, or technical errors? |
| Clarity | Is the writing concise, coherent, and easy to read? |
| Value / Insight | Does it offer a useful perspective instead of generic filler? |
| Engagement | Does it have a strong hook and a clear call to action? |
| Tone Fit | Is the post professional, clear, and accessible? |

### 3. Apply the pass/fail rules

Use the following strict logic:

- **FAIL** if `Factual Correctness < 4`.
- **FAIL** if the total of all five scores is `< 20`.
- **PASS** if neither failure condition is met.

The factual-correctness threshold is a zero-tolerance rule for hallucinations and material inaccuracies.

### 4. Analyze failures

For every failed post, identify the systemic failure rather than only rewriting the output.

| Failure category | Typical cause | Recommended fix |
| --- | --- | --- |
| Incorrect or Hallucinated Content | Missing context or grounding | Add source text, product facts, campaign details, or topic background to the prompt. |
| Low Informational Value | Generic pattern completion without enough topic reasoning | Add a reasoning scaffold that asks for specific, non-obvious insights before drafting. |
| Instruction Non-Compliance | Vague wording or unclear constraints | Replace negative or ambiguous constraints with direct positive instructions. |
| Poor Framing | No clear stylistic target or examples | Add a defined persona and a few strong examples for the model to imitate. |

If a recurring pattern does not fit these categories, create a new category with a clear definition and likely root cause.

### 5. Improve the system prompt

Choose the most relevant failure category and make a focused change to the n8n system prompt. The fix should target the diagnosed cause—for example, adding context for hallucinations or examples for weak framing.

### 6. Run regression tests

After updating the workflow:

1. Re-run the inputs that previously failed.
2. Re-run at least one input that previously passed.
3. Compare the new outputs with the originals.
4. Confirm that targeted failures improved without breaking previously successful cases.

## Calibrate Jev against human labels

Compare `Jev_Status` with the human `Status` column. Inspect false passes (human FAIL, judge PASS) and false fails (human PASS, judge FAIL). Human feedback and scores are excluded from the request to avoid label leakage. Unlabeled rows, errors and skipped rows do not count as agreements.

Refine the descriptive criteria in `src/judge.js`, increment `RUBRIC_VERSION`, and rebuild the workflows with `npm run build:workflows`. Keep a separate set of human-labeled posts untouched while tuning, and evaluate it after freezing the rubric. The default model is pinned to `jev-1.13.0`; the confidence threshold of `0.7` is a starting point, not a validated accuracy guarantee.

## Workbook Tabs

- **Evaluation Log** — original posts and human grades, reference inputs, and separate Jev scores, confidence, review flags and raw responses.
- **Failure Analysis** — recurring failure categories, counts, and recommended fixes.
- **Failure Traces** — detailed records for failed cases and their human feedback.
- **Jev Review** — formula-based agreement, false passes/fails, review counts and row comparisons for the first 100 data rows. Scores stay blank until a real run succeeds.
